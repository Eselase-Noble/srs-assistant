# Technical spike: local English/Twi pipeline

Proves the hard parts on real audio before we build the app (see `../docs/02-local-tech-stack.md` §6).
Everything runs locally on CPU. After the first model downloads, no internet is needed.

## Setup (already done on this machine)
```powershell
winget install astral-sh.uv Gyan.FFmpeg Ollama.Ollama
ollama pull qwen3:8b; ollama pull nomic-embed-text
cd C:\Projects\SRS\spike; uv sync
```
Optional, for speaker diarization (gated model, free account):
1. Accept the terms at https://huggingface.co/pyannote/speaker-diarization-community-1
2. Optionally request access to Kasanoma at https://huggingface.co/Kennethdot/kasanoma (manual approval)
3. `uv run hf auth login` and `uv sync --extra diarize`

## Your test recordings → put them in `audio/`
Use your phone or laptop. Any format works (m4a, mp3, wav, webm…). 1 to 3 minutes each is enough.

| File name (suggested) | Content |
|---|---|
| `english.m4a` | You (or two people) discussing a system you'd want, in English |
| `twi.m4a` | The same kind of conversation entirely in Twi |
| `mixed.m4a` | Natural English/Twi code-switching, the way your stakeholders really speak |
| `group.m4a` (optional) | 3+ people talking, to test speaker separation |

For each clip, also write what was actually said in `audio/<name>.txt` (at least the Twi ones), so we can compare the models' output against the truth.

`audio/sample_english_tts.wav` is a synthetic test generated by `make_sample.ps1` (Windows text-to-speech). It is for smoke-testing only.

## Live listening (record from the computer in real time)
```powershell
uv run python live_record.py --list-devices                 # see microphones / speakers
uv run python live_record.py --name client-interview --consent "Kofi agreed verbally"
uv run python live_record.py --name workshop --source mic   # in-person only
uv run python live_record.py --name call --no-transcribe    # record only, no live transcript
```
Captures **MIC** (your microphone) and **SYSTEM** (what the computer plays, e.g. the other side of a
Zoom/Teams/WhatsApp call) at the same time. Audio is saved as 15-second chunks while recording, so
nothing is lost if something crashes. Press **Ctrl+C** to stop. You get `sessions/<date>_<name>/` with
`mic.wav`, `system.wav`, `mixed.wav`, `transcript_live.md` and `session.json`.
The live transcript is an English draft. Lines marked *non-English* get the Twi pass after the session.
On calls, **use headphones**, otherwise the mic re-records the speakers.

## After the session: transcript and requirements in one step
```powershell
uv run python process_session.py                  # newest session, uses the live transcript
uv run python process_session.py --retranscribe   # redo speech to text first for better accuracy
```
This writes `transcript.md`, `requirements.md` and `requirements.json` into the session folder.
Ollama has to be running.

## Run the analysis steps one at a time
```powershell
uv run python asr_compare.py                     # every model on every clip -> results/asr_report.md
uv run python translate_twi.py --from-asr results/asr_twi.json --model akan-turbo
uv run python diarize.py audio/group.m4a --asr results/asr_group.json --model whisper-turbo
uv run python extract.py results/asr_english.json --asr-model whisper-turbo --llm qwen3:8b
```

|---|---|---|
